## 已明确的需求

基于用户提供的需求，讨论其合理性与可能漏洞，探索实际可行方案，带来思路并推进设计（BS-Q001）。主要服务用户没做过的任务，帮助探讨边界，由用户手动触发（BS-Q002）。

用户无需先说清卡点。发现需求不足、边界与阻碍是 Skill 应帮助完成的工作，不能把它作为用户先完成的输入条件。

按 2026-10-12 体系建设报告优先研究成熟上游方法，依据真实设计复用、适配；不自行另造一套方法。每项来源分别记录作者、许可证与固定版本。报告作为参考规划，未被明确修改的后续访谈决定继续有效。

## 设计与文档写作分工（BS-Q003）

Z-brainstorming 负责设计。设计完成时，由它调用 Z-design-document，遵循后者的 SOP 生成合规、清楚、可读的架构、接口和技术设计文档。

Z-design-document 的职责是规范文档编写，保障每次输出的质量；本身不参与设计。“交给 Z-design-document 继续设计”的旧问题前提已撤回，原问题与回答保留。

这项关联要求来自当前 Skill 的访谈，作为后续 Z-design-document 独立访谈的已知输入。具体写作规范待访谈，不提前定义或实现下一 Skill。此运行时关联不改变 Z-deep-interview 独立单线程的执行要求。

## 专家设计与对抗式审查（BS-Q004）

Z-brainstorming 的设计与检查需要专门专家 Agent 参与，通过对抗式审查保障设计合理性与可读性。设计决策仍属于 Z-brainstorming 工作流，文档编写遵循 Z-design-document 的 SOP。

当前只确认专家参与及审查方式；具体专家绑定、设计与检查的分工、独立性、意见处理、返修和通过标准、最终用户确认规则仍待访谈。专家执行继续采用全局要求的 goal、boudaries、SOP(each run) 三个专门标题。此项不改变当前需求访谈的独立单线程方式，各 Agent 完整需求后续分别访谈。

## 访谈方式纠正

不预先给答案、推荐选项或惯例化方案对照。介绍与当前问题相关的背景和依赖，帮助拆解后提出一个开放问题。也不要求用户先准确识别真实任务的所有卡点。助手解释与用户原话分开，全部历史保留，当前结论按最新回答更新。

## 已核验的上游依据

[Superpowers brainstorming 来源与适配依据](../../references/superpowers-brainstorming.md)：7.0.0，固定提交 bb92a77741419a4ab5f06e711a283343f1ada0c3，Jesse Vincent，MIT。

上游先判断已知信息，开放提问，了解约束与已有项目，探索并筛选方向，分段复述；项目级任务形成书面设计，经检查和用户确认后进入计划。源码不要求在开场固定给几个推荐选项。

这些是核验后的参考事实，不表示所有上游行为已成为 Z 需求。手动触发采用用户要求；调用 Z-design-document 已由 BS-Q003 确认；专家参与设计与检查及对抗式审查已由 BS-Q004 确认。直接构建、原型、浏览器、自动提交及其他后续调用尚未确认，具体专家与审查契约也仍待明确。本次仅阅读与分析，未安装或移植。
