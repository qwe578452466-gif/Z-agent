## 背景与目标

你要在进入开发流程前，把常用 Skill、Agent 或工程需求问清楚。访谈对象可能只有一句想法，也可能不了解相关背景和可行方向，因此访谈需要帮助理解和拆解问题。

旧版本能记录对话，却没有稳定形成让人看懂的总结。Z-deep-interview 要同时完成讲解、缺口指导、逐题记录和清楚总结，为后续设计提供需求依据。

## 第一层：人类容易理解的结论

1. **直接使用、独立执行。** 首期提供通用 SKILL.md，在开发前由用户直接调用，单线程运行，不与主 Agent、专家 Agent 或其他 Skill 联动。Agent 可以是被定义的需求对象。
2. **从一句想法开始。** 文档、代码和约束为可选输入。缺少信息时由访谈逐步补齐。
3. **先帮助理解，再讨论选择。** 每轮一个问题；模糊问题先讲背景、依赖与取舍，帮助拆解。AI 主动提出缺口、指导和建议怎样补齐，再回到原问题。
4. **每题每答直接保存 JSON。** 保存原问题、每次回答、状态、轮次和评分依据；原文与助手解释分开。宿主不能直接保存 JSON 文件时，直接终止。
5. **历史全部保留，最新内容优先。** 同一事项按最新访谈内容迭代当前需求与既有项目；未被修改的其他事项保留。恢复参照 OMC 的问题状态和已回答记录，接续待答问题。
6. **问清楚再收尾。** 默认 Deep；20 轮不是强制停止点，仍有关键未决项就继续深度访谈。清晰度分数用于发现缺口，不能代替需求完整性。用户明确停止或取消时保存可写入的进度并结束当前访谈，未确认的需求不自动进入下一项。
7. **形成易读材料。** 输出需求规格 Markdown、访谈记录、JSON 状态和交接摘要。总结按“示例 → 背景 → 双层总结”组织，让人看懂；不增加独立理解测试。
8. **详细设计在后续。** 访谈整理需求、接口、约束和已有验收要求；具体实现、设计案例、边界细化、存储布局和记录器实现留到后续设计开发。
