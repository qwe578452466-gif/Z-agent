# 专家 Subagent 执行模板 v0.3

所有专家 Subagent 的首次执行、重试和会话恢复都使用 [execution.md](../templates/subagent/execution.md)。执行说明必须只有以下三个二级标题，顺序、大小写和拼写固定，`boudaries` 保留用户指定的拼写：

```markdown
## goal

本次任务动态生成的执行目标、输入、产物和验收条件。

## boudaries

本次任务动态生成的仓库、写入范围、只读范围、约束和有效授权。

## SOP(each run)

对应专家总结并维护的操作规范，本次引用的版本必须严格遵守。
```

其他执行信息放在对应标题之下，不新增同级标题、改名或将三个标题合并。正文使用列表、段落或代码块；输入中含有同级标题时转为引用或代码块，不能改变模板结构。这些标题属于执行说明，结果仍使用 Result 契约。

## 内容来源与唯一事实源

| 标题 | 内容来源 | 更新方式 |
|---|---|---|
| `goal` | `task.goal`、inputs、outputs、acceptance_criteria | 主 Agent 依据当前任务生成；不能沿用另一个任务的目标 |
| `boudaries` | `task.scope`、required_capabilities、角色限制和宿主实际授权 | 每次分派、重试或恢复时核对；模板不扩大任何授权 |
| `SOP(each run)` | `task.sop_ref` 指向的专家 SOP | 专家总结和维护；分派时嵌入固定版本的规则原文 |

执行模板是呈现格式，不是新的业务真相来源。`boudaries` 对应底层 `scope`，不另设一份可以与 scope 漂移的任务边界。目标、产物或基线改变时按任务契约创建新任务。

## SOP 的形成与维护

1. 专家依据专业方法、已确认知识和执行反馈总结步骤，填写 [sop.json](../templates/subagent/sop.json)；模板只是起点，不能自动算作专家总结。
2. 保存 role_id、版本、真实作者、参考资料、经验来源 run_id，以及有稳定 ID 的有序 rules。每条规则标明 every_run 或有明确条件的 conditional。
3. 专家核对规则的适用性后设为 confirmed。未确认、作者未知或已 retired 的 SOP 不能进入实际执行。
4. 主 Agent 锁定 SOP 路径、版本和内容 SHA-256，将规则正文按顺序嵌入第三个标题。专家 SOP 的 role_id 必须与 Task.owner_role 一致。
5. 每次执行结束，专家可以提出总结和下一版本。已确认版本和正在执行的任务快照保持不可变；采用新版本时建立新任务，不改写历史。

SOP 的稳定性指同一版本保持不变，允许在有证据和专家核对后发布新版本。规则不得把任务相关的硬件假设、目录或验收容差永久固定为所有任务的事实。

## 每次执行的校验

进入 ready 前，除原任务条件外，还必须确认 SOP 为 confirmed，文件存在、版本及 digest 匹配、作者属于该专家角色。三段正文必须非空，模板占位符全部解析，动态目标与边界符合任务契约，SOP 条文未被临时删改。

重试和恢复仍执行 SOP 的每次启动检查；可复用已经核实的产物，不能省略授权、基线和检查点核对。有效授权缩小时暂停或按更小范围执行，不能凭旧模板继续访问资源；扩大任务范围需要新任务。

SOP 不能扩大宿主授权或任务边界。严格遵守的步骤超出边界、依赖缺失或无法适用时先报告 blocked，写明冲突和所需动作；不能为了继续执行而临时改写 SOP。未知硬件仍标为 pending。

## 执行结果与独立审查

`Result.sop_checks` 按 SOP 规则 ID 和顺序逐条记录 outcome、evidence_ids 和 reason：

- followed：步骤已执行，关联可核验的证据。
- not_applicable：仅适用于条件不成立的 conditional 规则，必须说明理由。
- blocked：前提缺失或与边界冲突，必须说明原因。
- violated：实际违反规则，不能报告 completed 或验收通过。
- not_run：明确没有执行，不能描述为已遵守。

必需 SOP 规则不可省略；every_run 不能标成 not_applicable。未加载 SOP 的阻塞计划可以留下空检查列表，但必须记录缺失原因；completed 必须有检查记录，且不能存在 blocked、violated 或 not_run。

独立 Reviewer 检查三标题、目标与边界、锁定 SOP 的版本和原文，以及逐条遵守证据。结构校验和执行者自评不能独自证明实际遵守；宿主适配、渲染器与调度器在后续实现这些运行时检查。

## 版本变化

0.2 新增必需的 Task.sop_ref 和 Result.sop_checks；0.3 将本项目 Skill 标识统一为 Z-{skill}。旧版本运行记录不能直接宣称符合新契约，也不原地改写历史；恢复旧任务需要显式迁移或新建任务。仓库中的未执行示例已同步到 0.3。
